## 常见问题

### 1. `node --version` 显示 v18 或更低

你机器上默认 node 可能是 v18。用 nvm 切到 v24：

```bash
source ~/.nvm/nvm.sh
nvm use 24
node --version   # 应显示 v24.x
```

之后在**同一个终端**里继续 `npm install` / `npm run dev`。如果嫌每次都要 source，把
`nvm use 24` 加进 `~/.zshrc`。

### 2. MySQL 起不来（`docker compose` 报 3306 被占 / healthcheck 失败）

多半是本机已经有一个 MySQL 在 3306 端口。两个办法二选一：

- 停掉本机那个 MySQL，再 `docker compose up -d`
- 改 `docker-compose.yml` 里 mysql 的 `ports` 为 `"3307:3306"`（对外换端口，容器内部不变）

**判断**：`lsof -iTCP:3306 -sTCP:LISTEN` 有输出就是被占。

### 3. hsjday 路径怎么配

后端读数据的路径优先级：**环境变量 > `.env` > 代码默认值**。

- 演示模式：用 `STOCK_HSJDAY_ROOT="$PWD/data/demo_hsjday"` 前缀启动 uvicorn
- 真实数据：默认就是 `~/Desktop/每日复盘/hsjday`，不用配；不在这个位置就改 `.env` 里的
  `STOCK_HSJDAY_ROOT`
- 容器里：docker-compose 已经把 `~/Desktop/每日复盘/hsjday` 挂到容器内 `/data/hsjday`，不用改

### 4. 端口被占用（8000 / 3000 / 80）

```bash
# 查是谁占着
lsof -iTCP:8000 -sTCP:LISTEN
# 换成别的端口启动（以 8001 为例）
.venv/bin/uvicorn main:app --app-dir apps/api/src --port 8001
```

前端改端口：`npm run dev -- -p 3001`。改完端口后，前端访问 API 走的是
`next.config.ts` 里的 rewrite，目标端口 `API_ORIGIN` 默认 `http://localhost:8000`，
如果后端换了端口，启动前端时加环境变量：

```bash
API_ORIGIN=http://localhost:8001 npm run dev
```

### 5. npm 装依赖慢 / 报 `ERESOLVE`

`.npmrc` 已指向 npmmirror。如果还慢，先清缓存再装：

```bash
cd apps/web
npm cache clean --force
npm install
```

若报 `ERESOLVE`（依赖冲突），用 `npm install --legacy-peer-deps` 兜底。

### 6. Playwright 报「浏览器没安装」

```bash
cd apps/web
npx playwright install chromium
```

### 7. Docker 报「Cannot connect to the Docker daemon」

Docker Desktop 没启动。打开 Docker Desktop，等托盘图标变绿后再 `docker compose up -d --build`。

## 上传前最后一道自检（跑完上面 5 组之后）

用「当前登录用户名」拼出本机绝对路径前缀，检查仓库里有没有泄露（用 `git grep` 比
`xargs grep` 更稳，不会被中文文件名干扰）：

```bash
cd ~/Desktop/stock-platform
# 当前工作树（已提交的文件）
git grep -l "/Users/$(whoami)" HEAD 2>/dev/null
# 全部历史提交
 git grep -l "/Users/$(whoami)" $(git rev-list --all) 2>/dev/null
```

**预期输出**：两条命令都**空**（没有任何文件包含你的本机绝对路径 `/Users/<你的用户名>`）。
这一步是硬门槛——**只要有输出，就先别上传**，回来把那个文件加进 `.gitignore` 或改掉绝对路径。

> 提示：`$(whoami)` 会在你本机自动展开成你的用户名，所以这条命令本身不含任何
> 具体用户名，不会“自己查到自己”。
