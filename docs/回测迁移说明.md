# 回测迁移说明（阶段 4）

> 目的：把 Jeremy 现用脚本（`top5_verify.py` 的次日验证、`kdj_b1_backtest_all.py`
> 的持有 N 日胜率统计）里的「验证/回测」思路，迁移进 `packages/backtest`，
> 并补上 A股真实约束（T+1、涨跌停、成本、前复权）。本文档记录口径定义、
> 与旧脚本的一致性结论、真实历史回测结果、以及遗留 TODO。

---

## 0. 总原则

- **信号验证优先做对**：Jeremy 现在真正在用的是 `top5_verify.py` 的「次日命中率」，
  本阶段先保证信号验证模式与它口径一致，再谈组合回测。
- **宁缺毋滥**：回测算错比没有回测更危险。每个统计指标都有明确的数学定义和单测，
  不确定的口径（如 3-2-2-2 分步建仓）宁可不做，也不做错。
- **A股约束写进代码**：T+1、涨跌停不可成交、成本（佣金/印花税/过户费/滑点）、
  前复权口径，全部收敛到 `packages/backtest/backtest/` 的纯函数层，单测锁死。
- **交易日历必须做对**：持有期计算依赖交易日，顺手把阶段 1 遗留的
  「工作日=交易日」近似修掉（见第 1 节）。

## 1. 交易日历修复（阶段 3 遗留）

阶段 1 的 `market.calendar.is_trading_day` 只排除周末。阶段 4 改为：

- **从 hsjday 实际交易日反推**（任务书推荐做法，比硬编码节假日表更可靠）：
  任意 A股真正的交易日，市场上至少有一只标的有日线；因此「所有 .day 文件出现过的
  日期集合」就是完整交易日集合，「数据末日之前的工作日」不在其中即为休市日。
- 由 `scripts/make_trading_calendar.py` 生成静态表 `market/holidays.py`
  （124 个休市日，覆盖 2020-01-01 ~ 2026-08-27），`is_trading_day` 运行期 O(1) 查询。
- 数据末日之后的日期不在表内，`is_trading_day` 回退到「工作日=交易日」近似
  （未来节假日未知，合理降级）。
- 新增 `trading_days(start, end)` 与 `shift_trading_day(day, n)`，供回测持有期与
  衰减窗口做交易日算术。

验证：春节（2026-02-16~20）、国庆（2025-10-01~07）等长假休市日已正确排除，
`tests/unit/test_calendar.py` 锁死。

## 2. 回测引擎结构（`packages/backtest/`）

| 模块 | 职责 |
|---|---|
| `config.py` | `CostConfig`（佣金万2.5/最低5元、印花税千1卖出、过户费沪市万0.1、滑点千1）、`PortfolioConfig`（个股≤20%、预备队20%、持有期/止盈止损）、`BacktestConfig`（持有期列表、无风险利率、复权模式、衰减窗口） |
| `execution.py` | 涨跌停价（四舍五入到分）、一字涨停买不进、跌停卖不出、佣金/印花税/过户费/滑点、一次完整买卖净收益 |
| `forward.py` | 持有 N 日收盘对收盘前向收益（对齐 top5_verify） |
| `stats.py` | 胜率/平均/中位数/盈亏比/分位数/标准差/最好最差/直方图 + 净值曲线/最大回撤/年化夏普 |
| `portfolio.py` | 组合回测：按信号建仓、T+1、涨跌停、成本、止盈止损、净值曲线 |
| `engine.py` | 编排：信号 → 验证报告（按策略/板块聚合 + 衰减）/ 组合报告 |
| `models.py` | pydantic 结果模型（供 API JSON + 前端展示） |

依赖关系：`backtest` 只依赖 `stock-strategies`（Signal）、`stock-market`（涨跌停/日历）、
`stock-datasource`，不反向依赖 API。

## 3. 两种回测模式

### 3.1 信号验证模式（对应 top5_verify.py，优先做对）

- 信号在 T 日收盘后触发；**持有 N 个交易日收益 = close[T+N] / close[T] - 1**
  （收盘对收盘，无成本）。
- 与 `top5_verify.py` 的「次日验证」完全一致：N=1 的正收益占比 == 旧脚本命中率。
- 停牌：标的数据里没有停牌日 K 线，索引式前向直接跳到复牌那根 → 等价「持有跨越停牌」。
- 数据末尾不足 N 日 → 该持有期收益为 None，统计时剔除。
- 输出：按策略、按板块聚合的 `HoldReturn`（胜率/平均/中位/盈亏比/分位数/直方图）。

### 3.2 组合回测模式

- 按信号在 T+1 开盘买入，固定持有期或止盈止损离场，输出净值曲线。
- A股约束全部落实：T+1（当日买入次日才能卖）、一字涨停买不进、跌停卖不出、
  佣金/印花税/过户费/滑点。
- 仓位规则（TOOLS.md）：单只 ≤ 20%，保留 20% 预备队（最多动用 80% 资金）。
- **简化（已记录）**：3-2-2-2 分步建仓未实现，按一次性建仓近似；止盈止损按收盘价
  判断（不用盘中高低点）；同标的同日只建一笔、已持仓不加仓。

## 4. 统计指标口径

- **胜率** = 正收益占比（与 top5_verify 命中率一致）。
- **盈亏比** = 平均盈利 / |平均亏损|；无亏损样本时记 None。
- **最大回撤** = 净值曲线从峰值到谷底的最大跌幅（≤ 0）。
- **夏普** = (年化超额收益) / (年化波动)，无风险利率可配，样本 < 2 或波动为 0 记 None。
- **持有 N 日收益分布** = 固定等宽直方图（[-20%, +20%] 每 2% 一桶，两端截断），
  保证跨数据可比。
- **按策略 / 按板块拆分**：板块先用「市场板块」（主板/创业板/科创板/北交所）简化映射，
  真实行业板块（申万/东方财富）需名称快照，列为 TODO。

---

## 5. 策略衰减监测

- 滚动窗口（交易日）胜率曲线：某策略在「最近 W 个交易日」内所有信号的
  `decay_hold_days`（默认 1 日）正收益占比，随时间滑动。
- 支持多个窗口（默认 20 / 60），输出 `DecaySeries`（date / win_rate / n）。
- 这是 Jeremy 最需要的功能——判断某个策略是不是失效了。

## 6. 与 top5_verify.py 的一致性验证（验收核心）

用旧脚本的选股历史 `tools/stock_pick_history.json`（20 条记录、94 个有效样本），
分别按 top5_verify 口径（hit = 次日涨跌 > 0）和回测引擎 forward_returns(N=1)
口径（正收益占比）算命中率：

| 口径 | 命中率 |
|---|---|
| top5_verify.py（hit/有效数） | 39.36% |
| 回测引擎 N=1 胜率 | 39.36% |

**结论：完全一致。** 两者都是「次日收盘 / 当日收盘 - 1 > 0」，top5_verify 的
hit/flat/miss 三分类（-2% 阈值）只是额外切一刀，不影响命中率。验证脚本
`scripts/verify_top5_consistency.py` 可复现。

### 7.2 持有期衰减（胜率随持有天数变化）

- **etf_accumulation 是唯一「越拿越强」的策略**：胜率 59.6%（1 日）→ 81.0%（20 日），
  平均收益 +0.75% → +6.03%。底背离 + 深度回撤的 ETF 反弹是慢变量，持有越久越兑现。
- **macd_resonance 是「越拿越亏」的典型**：胜率 43.8% → 28.0%，20 日平均收益 -6.00%，
  月周共振选出的标的在 1~2 个月内系统性走弱，长持有是负资产。
- **b1b2b3 / pin30 缓慢衰减**：随持有期拉长胜率从 46~48% 掉到 38~40%，平均收益由
  略负变明显负（-0.13% → -1.60%）。信号偏「超卖左侧」，短期不反弹就持续阴跌。
- **stealth_rally 最平稳**：胜率 48~50% 几乎不随持有期变化，平均收益在 +0.45% 内
  窄幅震荡，是五个里唯一「持有期中性」的策略。

### 7.3 策略衰减（滚动 20 日胜率随时间变化）

结论：**没有策略出现单调的「失效式」衰减**，但有一段共同的 6 月初市场低谷，
以及个别策略的显著下坡。

- **共同低谷（2026-06-03 ~ 06-22）**：五个策略的滚动胜率几乎同步下探——
  b1b2b3 36.9%、macd_resonance 39.2%、pin30 38.4%、stealth_rally 38.7%（6/22）、
  etf_accumulation 29.6%（7/23，滞后）。这是市场级别的风格切换，不是单一策略失效。
- **stealth_rally 下坡最陡**：5/18 峰值 49.0% → 7/8 谷底 35.4%，7 周掉了 13.6 个百分点，
  是唯一出现「明确往下走」的策略；但 8 月强力反弹回 56.2%，属于周期性而非永久失效。
- **pin30 温和走弱**：4~5 月 50~51% → 6 月初 38.4%，之后只回到 47~48%，未回到前高，
  斜率约 -2.7pp/100 交易日，是「缓慢下滑」的代表。
- **macd_resonance 长期最弱但平稳**：滚动胜率始终在 39~48% 徘徊，从未真正站上 50%，
  不往下走是因为「本来就在低位」——它是「持续跑输」而非「正在失效」。
- **b1b2b3 最稳定**：37~51% 震荡、斜率约 +0.9pp/100 交易日（基本走平），没有方向性。
- **etf_accumulation 胜率最高但样本最噪**：滚动胜率 30%~66% 大幅摆动（窗口 n 只有
  34~277），7 月曾掉到 29.6%，8 月末回到 66.4%，单看曲线无法判定稳定，需更长样本。

### 7.4 组合回测（信号 → 建仓 → 净值）

| 指标 | 值 |
|---|---|
| 总收益 | +3.26% |
| 最大回撤 | -19.19% |
| 年化夏普 | 0.275 |
| 成交 | 110 笔（建仓 125、跳过 455330） |

组合层 +3.26% 的正收益几乎全部来自 etf_accumulation 的少数高质量信号
（其余四个策略整体为负贡献），而 20% 单票 + 一次性建仓 + 收盘止盈止损的简化
口径放大了回撤（-19.19%）。夏普 0.275 说明组合在当前简化下不具备可交易的
风险调整后收益。

### 7.5 一句话结论

**当前五个策略里只有 etf_accumulation 有真实超额，其余四个（尤其 macd_resonance）
在本区间跑不赢 50% 胜率的掷硬币基准；stealth_rally 曾出现明确衰减但 8 月已反弹。**
回测口径为收盘对收盘、不含成本、T+1 仅组合层落实，实际交易还要再打折。

## 8. 遗留 TODO

1. **3-2-2-2 分步建仓**：组合回测当前一次性建仓，分步建仓（首笔 30% + 三次 20%
   分批挂单）需按日模拟，属后续优化。
2. **真实行业板块**：`classify_board` 只按市场板块（主板/创业板/科创板/北交所）划分，
   接真实行业板块需股票名称/行业快照（阶段 5 调度器一并解决）。
3. **复权因子**：`market.adjust` 的 `AdjustMode.FORWARD` 是约定默认，但 hsjday 是
   不复权原始数据、复权因子未接入；当前引擎按原始价直通（有单测锁死「不重复复权」），
   接复权因子后需在 `execution`/`forward` 入口统一应用。
4. **API 回测性能**：`POST /backtest/runs` 同步逐日全市场扫描（单日约 1 分钟），
   大批量历史回测建议用 `scripts/run_backtest.py` 离线跑批（已支持 fork 多进程），
   API 面向小范围演示。是否引入队列/缓存列为阶段 5 议题。
5. **止盈止损用盘中高低点**：当前按收盘价判断，盘中触发的高/低点是更精细的口径。
