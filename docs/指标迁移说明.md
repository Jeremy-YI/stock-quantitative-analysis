# 指标迁移说明（阶段 2）

> 目的：把 `~/.openclaw/workspace/tools/` 下生产脚本里的 KDJ / RSI / 量能逻辑，
> 迁移进 `packages/indicators`，并保证**数值与旧脚本一致**，迁移后策略结果不变。
> 本文档记录每个指标「旧实现 → 新实现」的差异和改动理由，供 Jeremy 判断策略
> 结果变化是否合理。

---

## 0. 总原则

- **能对齐就对齐**：新实现默认按旧脚本公式原样复刻，用一致性测试锁死（见 `tests/unit/test_consistency.py`，
  用同一份 600519 fixture，新实现 vs 从旧脚本抽出的参考实现，逐点 1e-6 内一致）。
- **旧脚本本身不标准/有 bug 时才改**，且只在 `docs/` 里记录清楚，不在代码里偷偷改。
- 旧脚本里的指标有两套实现（A股共享库 vs 美股回测脚本），本文逐一说明选择了哪套、为什么。

## 1. KDJ(9,3,3)

### 旧实现（两套）

**A 套 —— 共享库版（采纳）**，来源：
- `daily_stock_picker.py::calc_kdj`（A股选股共享库，被 `stealth_rally_scanner.py` 等 import）
- `us_indicators.py::calc_kdj`（美股指标，同公式）
- `us_pin30_scanner.py::quick_kdj`（美股单针扫描，同公式）

公式：

```
RSV = (close - LLV(low,9)) / (HHV(high,9) - LLV(low,9)) * 100   （HHV==LLV 时取 50）
K   = 2/3 * K_prev + 1/3 * RSV        （初始 K=50）
D   = 2/3 * D_prev + 1/3 * K          （初始 D=50）
J   = 3K - 2D
前 8 根无完整窗口 → 填充 50
```

**B 套 —— 美股回测版（未采纳）**，来源 `kdj_b1_backtest_all.py::signals`：

```
RSV = (c - LLV(l,9)) / (HHV(h,9) - LLV(l,9) + 0.001) * 100   # 分母 +0.001 防零
K   = SMA(RSV,3,1)  →  K[i] = (1*RSV[i] + 2*K[i-1]) / 3, K[0]=RSV[0]   # 首值种子=RSV[0]
D   = SMA(K,3,1)
```

### 新实现

`packages/indicators/kdj/kdj.py::calc_kdj`，**完全复刻 A 套**：
- 前 `period-1` 根填充 50，初始 K=D=50，HHV==LLV 时 RSV=50。
- 支持自定义 `period`（默认 9），平滑权重固定 1/3（即通达信 9,3,3）。

### 差异 & 为什么

| 项 | 旧（B 套） | 新 | 说明 |
|---|---|---|---|
| RSV 分母 | `+0.001` 防零 | 直接判断 `HHV==LLV` 取 50 | `+0.001` 会轻微压低 RSV（尤其高价股），且是隐藏魔法数；A 套用显式分支更干净 |
| K 首值种子 | `K[0]=RSV[0]`（窗口不足也硬算） | 前 8 根填充 50 | A 套约定：没有完整 9 日窗口就不该有 RSV |
| 平滑 | `SMA(rsv,3,1)` 递推 | `2/3*prev + 1/3*cur` | 两者数学上等价（SMA(x,3,1) ≡ x/3 + 2prev/3），只是写法不同 |

**选择 A 套的理由**：`daily_stock_picker.py` 是 A股脚本的事实共享库，`stealth_rally_scanner`、
`us_pin30_scanner`、`us_indicators` 三处都一致；而 B 套只出现在 `kdj_b1_backtest_all.py`
这一个美股回测脚本里。量化平台面向 A股，应以 A 套为准。

> ⚠️ 迁移到 B 套脚本（美股 KDJ_B1 回测）时，KDJ 数值会与旧回测**略有差异**，
> 原因是 `+0.001` 防零和首值种子不同。若将来要复现那份美股回测，需要单独对齐。

## 2. RSI(14)

### 旧实现

来源：`daily_stock_picker.py::calc_rsi`（A股，返回完整序列）；
`us_indicators.py::calc_rsi`（美股，同样 Wilder 但只返回最后一根）。

公式（标准 Wilder 平滑）：

```
delta = close[i] - close[i-1]
gain = max(delta, 0), loss = max(-delta, 0)
初始 avg_gain = mean(gain[:14])   # Wilder 首值 = 简单平均
初始 avg_loss = mean(loss[:14])
之后 avg_gain = (avg_gain*(period-1) + gain) / period
     avg_loss = (avg_loss*(period-1) + loss) / period
RS  = avg_gain / avg_loss
RSI = 100 - 100/(1 + RS)
前 14 根填充 50
```

### 新实现

`packages/indicators/rsi/rsi.py::calc_rsi`，复刻 Wilder 平滑 + 完整序列 + 前 14 根填 50。
支持自定义 `period`（默认 14）。

### 差异 & 为什么

| 项 | 旧 | 新 | 说明 |
|---|---|---|---|
| 输出 | `us_indicators.py` 只返回最后一根 | 完整序列（与 `daily_stock_picker.py` 一致） | 平台要画图，必须是序列 |
| **无波动特例** | `avg_loss == 0` 一律返回 100 | `avg_loss == 0 且 avg_gain == 0` 时返回 50 | **这是旧脚本的 bug**：完全无波动（14 根平盘）时 avg_gain 和 avg_loss 都为 0，旧代码进 `avg_loss==0` 分支返回 100，标准定义应为 50（中性） |

> 修正只影响「连续 14 根收盘价完全不变」这种极端情况；真实行情数据不会触发，
> 一致性测试用 600519 真实切片比对时新旧结果完全相同。

## 3. 量能（MAVOL / 量比 / 价量关系）

### 3.1 MAVOL1(5) / MAVOL2(10)

- 旧：`kdj_b1_backtest_all.py::ma(v,5)` / `ma(v,10)` —— 简单移动平均，窗口不足时用已有数据平均。
- 新：`calc_volume_ma` —— **完全一致**（含窗口不足的平均规则），一致性测试锁死。

### 3.2 量比

- 旧：`daily_stock_picker.py` 的 `vr = vol_now / avol5`，其中 `avol5 = 过去 5 日平均成交量（不含当日）`。旧脚本只算**最后一根**。
- 新：`calc_volume_ratio` —— 同样口径（当日 / 过去 5 日均量，不含当日），但输出**完整序列**。
  首根无前日可比取 1.0；前 5 根用已有前日数据平均（旧脚本只有最后一根，没有这个「预热期」定义，
  属于新扩展，已在函数 docstring 注明）。

### 3.3 价量关系（价升量增 / 价升缩量 / 价跌放量 / 价跌缩量）

- 旧：**没有现成的价量关系函数**（旧脚本只零散地在打分逻辑里用 `vr` 阈值判断放量/缩量，
  如 `daily_stock_picker.py` 里 `vr >= 0.8` 判缩量、`1.2 <= vr <= 3.0` 判温和放量）。
- 新：`classify_price_volume` —— 这是**新定义的**、集中化的判定，口径如下：
  - 价升/价跌：`close[i]` 相对 `close[i-1]`；
  - 放量/缩量：`volume[i]` 相对 MAVOL1（5 日均量，含当日）；
  - 输出中文标签：价升量增 / 价升缩量 / 价跌放量 / 价跌缩量 / 价平 / 量平 / 首根 `—`。
- 与旧打分逻辑的阈值（`vr >= 0.8`、`1.2 <= vr <= 3.0`）**不是一一对应**，价量关系是
  面向「看板展示」的粗分类，不是策略信号阈值。策略层迁移（阶段 3）仍应沿用旧脚本的具体阈值。

## 4. 一致性测试怎么保证「迁移不变」

- `tests/reference/legacy_indicators.py`：从旧脚本**原样抽取**的参考实现（只在测试用，不进生产代码）。
- `tests/unit/test_consistency.py`：用同一份 `600519_daily.csv` fixture：
  - `calc_kdj` vs `legacy_calc_kdj` 逐点 1e-6 一致；
  - `calc_rsi` vs `legacy_calc_rsi` 逐点 1e-6 一致（真实数据不触发平盘特例）；
  - `calc_volume_ma` vs `legacy_ma` 逐点一致；
  - `calc_volume_ratio` 最后一根 vs `legacy_volume_ratio_last` 一致。
- 黄金值 fixture（`600519_kdj_golden.csv` 等）由 `scripts/make_fixtures.py` 用**新实现**生成并提交，
  黄金值测试锁死回归，一致性测试锁死「新 == 旧」，两道保险共同保证迁移后数值不变。
