## 3. 四组因子发现的样本外验证（核心产出）

> 复现：`.venv/bin/python scripts/run_oos_factors.py`（sample=700 / seed=7 / 持有 5 日，
> 与阶段 8 因子研究同口径）。输出 JSON：`data/oos_factors.json`。
> 注：IS 数字与 docs/因子研究报告.md 有 ±1pp 差异（数据快照更新到 2026-08-28），
> 不影响方向结论。

### 3.1 F1 量比基准窗口：vr60 是否仍单调

**样本内结论**：vr60 完全单调（<0.6 → +1.99pp，>3.0 → -7.89pp）；vr5 方向反；vr20 无信号。

| 窗口 | vr60 <0.6 | vr60 >3.0 | vr5 <0.6 | 判定 |
|---|---|---|---|---|
| IS | +1.99pp | -7.89pp | +0.65pp | 单调 ✓ |
| OOS-A | +1.20pp | -7.91pp | -0.53pp | 单调 ✓ |
| OOS-B | **-5.48pp** | -10.46pp | +2.16pp | **缩量端失效** ✗ |
| OOS-C | +3.36pp | -13.33pp | -0.14pp | 单调 ✓ |

**判定**：**「放量（vr60>3.0）负超额」稳健（四段全负，且幅度单调加深）。
「缩量（vr60<0.6）正超额」环境依赖**——在 2024（OOS-B）完全反转成 -5.48pp。
即「放量追高必死」是硬结论，「缩量抄底」只在弱市/震荡市成立，遇到 2024 那种
缩量阴跌的年份会踩坑。

### 3.2 F2 MACD 水下多头 × 极缩量：最强格是否仍是最强

**样本内结论**：水下多头 + vr60<0.6 → +10.42pp（阶段 8 报告 +9.39pp），是最强组合。

| 窗口 | 水下多头+极缩（below_bull × vr60<0.6） | 判定 |
|---|---|---|
| IS | +10.42pp | 最强 ✓ |
| OOS-A | +4.09pp | 正，但非最强（水上多头 +4.42pp 略高） |
| OOS-B | **-3.97pp** | 失效 ✗（该年所有 MACD 状态 × 极缩全负） |
| OOS-C | +6.73pp | 最强 ✓ |

**判定**：**环境依赖**。失效点在 2024 且不是「水下多头」失效，而是「极缩量」失效
（OOS-B 里四个 MACD 状态 × 极缩格全部为负，与 F1 的 vr60<0.6 = -5.48pp 一致）。
「水下多头」作为右侧确认是稳健的，「极缩量」作为买点触发器在 2024 是反指。
由此衍生策略 `macd_volume_washout` 继承了这一环境依赖。

### 3.3 F3 均线多头因子：是否仍全部负超额

**样本内结论**：均线多头（5/13/25/75/120）全部负超额（追高反指）。

| 窗口 | 完美多头 | 短期多头 | 站上MA120 | 中期多头 | 判定 |
|---|---|---|---|---|---|
| IS | -1.06 | -1.56 | -1.95 | -2.43 | 全负 ✓ |
| OOS-A | -2.95 | -1.39 | -2.42 | -2.63 | 全负 ✓ |
| OOS-B | -3.10 | **+1.25** | -1.12 | -0.83 | 3/4 负 |
| OOS-C | -5.68 | -3.04 | -2.46 | -1.99 | 全负 ✓ |

**判定**：**稳健**。「完美多头」「站上 MA120」「中期多头」四段全负，「跌破 MA120」
四段全正（超跌）——均线多头是稳定反指，方向从没翻过。唯一例外是「短期多头」在
2024 一度 +1.25pp（可忽略的噪声）。**均线多头应继续作为排除项/反指，不是买入信号。**

### 3.4 F4 偏离度 U 形：是否仍成立

**样本内结论**：偏离度 (close-MA5)/MA5 呈 U 形（两端正超额、中间负超额）。

| 窗口 | 低端<-8% | -8~-4% | -2~0 | 4~8% | 高端>8% | 判定 |
|---|---|---|---|---|---|---|
| IS | +2.09 | +4.49 | -1.94 | +2.95 | +2.83 | U 形 ✓ |
| OOS-A | **-3.44** | +4.14 | -0.93 | -3.33 | -6.00 | 左正右负 ✗ |
| OOS-B | +8.60 | +4.48 | -1.76 | +3.97 | -3.99 | 混合 |
| OOS-C | +12.15 | +1.86 | +2.43 | -7.82 | -10.03 | 左正右负 ✗ |

**判定**：**U 形不稳健，需修正为「左端超跌反弹」**。真正稳健的是**左端（超跌，
尤其 -8~-4% 档四段全正）的正超额**；右端（追高 >4%）在 OOS-A/OOS-C 都是显著负超额
（-6.00 / -10.03pp），只有 IS 恰好为正。修正结论：**超跌（-8~-4%）买、追高（>4%）卖**，
而不是对称的「两端都好」。

## 4. regime filter 分策略配置 + 网格搜索（阶段 8 遗留 TODO #1）

**阶段 8 实测**：默认 filter 对均值回归类有效（washout 损失 -19.48%→-15.45%），
对深跌吸筹类有害（etf_accumulation +1.99%→-2.42%，因为 min_drawdown=-15% 挡掉了
它需要的深回撤）。

**本阶段落地**：
1. 各策略 config 新增 `regime_profile` 字段（新字段，不改阈值），分两类：
   - `mean_reversion`（均值回归：washout / stealth_rally / pin30 / b1b2b3 / double_bottom / macd_resonance）——避开强涨、要清淡、回撤 -15%~0。
   - `deep_accumulation`（深跌吸筹：etf_accumulation）——允许深回撤（下界 -40%）。
2. `market.regime.REGIME_PROFILES` + `RegimeFilterConfig.from_profile` 提供档位映射。
3. `PortfolioConfig.regime_by_strategy` 按策略名覆盖全局 filter。

### 4.1 三参数网格搜索（样本内做）

> 复现：`.venv/bin/python scripts/run_regime_grid.py`。输出 `data/regime_grid.json`。
> 网格：max_index_20d_return ∈ {0, 2, 4, 8, 15, 100%} × max_activity ∈ {0.8, 1.0, 1.2, 1.5, 3.0}
> × min_drawdown ∈ {-8, -15, -25, -40, -100%}，目标 = 组合总收益（损失最小化）。

| 策略类型 | 代表策略 | 最优阈值 | IS 收益 | 回撤 | 夏普 |
|---|---|---|---|---|---|
| 均值回归 | macd_volume_washout | r20<+2% 且 活跃<1.0 且 回撤>-25% | **+18.14%** | -12.12% | 1.337 |
| 深跌吸筹 | etf_accumulation | r20<0% 且 活跃<1.2 且 回撤>-15% | **+13.59%** | -7.24% | 1.401 |

> ⚠️ **这是样本内最优，存在选择偏差（过拟合）**。网格有 150 个点，挑最大收益几乎
> 必然高估。上面 +18%/+13.6% 需要样本外验证才能当真，§4.2 的「分策略」对比用的
> 是**原则性档位**（mean_reversion/deep_accumulation），不是网格最优值。

### 4.2 组合回测对比：无 / 全局 / 分策略 filter（样本内 IS，用原则性档位）

| 策略 | 无 filter | 全局 filter（默认） | 分策略 filter |
|---|---|---|---|
| macd_volume_washout（均值回归） | -19.47% / -31.98% / -1.480 | -15.44% / -27.95% / -1.382 | -15.44% / -27.95% / -1.382 |
| etf_accumulation（深跌吸筹） | +4.79% / -20.79% / 0.418 | +3.46% / -18.39% / 0.341 | **+4.79%** / -20.79% / 0.418 |

（格式：总收益 / 最大回撤 / 夏普）

**结论**：分策略 filter 解决了阶段 8 的「全局 filter 害了深跌吸筹」问题——
`etf_accumulation` 从全局 filter 的 +3.46% 恢复到无 filter 的 +4.79%（它的
`deep_accumulation` 档允许深回撤，不再被 min_drawdown=-15% 挡掉买点）；
`macd_volume_washout` 的 `mean_reversion` 档与默认 filter 一致，保持 -15.44%。

## 10. 全市场逐日扫描的内存修复（阶段 10，解锁 OOS-B/C）

阶段 9 把 OOS-B/C 未完成归因为「本机内存不够」。**这个归因是错的**：机器有 32GB，
问题在扫描器自己。用 5 个交易日 × jobs=4 做同口径对照（`/tmp/bench_scan.py`，
old = git HEAD 的旧实现，new = 修复后）：

| 指标 | 修复前 | 修复后 | 变化 |
|---|---|---|---|
| 父进程峰值 RSS | 714MB | **368MB** | -48% |
| 单 worker 峰值 RSS | 473MB | **267MB**（其中 ~250MB 是 COW 共享的 K 线） | -44% |
| 估算总足迹（父 + 4 worker） | ~2.6GB | **~0.45GB 物理**（RSS 相加 1.4GB，但 worker 页面是共享的） | -5.8x |
| 5 天扫描耗时 | 54.0s | 50.9s | -6% |
| 信号数 | 21441 | **21441** | 完全一致 |

### 10.1 四个根因（按影响排序）

1. **`Pool(initializer=..., initargs=(candles, ...))` 把整个宇宙 pickle 进每个 worker。**
   即使用 fork，`initargs` 仍要经 pipe 序列化：父进程一份 pickle buffer + 每个 worker
   一份**独立反序列化副本**。jobs=4 就是 4 份真实物理内存（每份 ~250MB）+ 序列化峰值。
   → **改成 fork 前在父进程写模块级全局**，worker 靠 copy-on-write 真共享。
   worker 只读不写这些 frame，页面永远不会被复制。
2. **布尔掩码切片 `df[df["date"] <= day]` 是复制，且一次性物化整个宇宙。**
   6000 只 × 6 策略 × 240 天 ≈ 上百万次 DataFrame 复制，每次都要重新分配 7 列数据；
   CPython arena 不把释放的内存还给系统，RSS 一路抬高。
   → **`strategies.slicing.DaySliceView`**：`date` 列预算成 int64 ordinal 数组，
   `np.searchsorted` 定位后用 `df.iloc[:pos]` **位置切片**（前缀切片是底层 ndarray 的
   视图，零复制），并且实现成惰性 `Mapping`——策略遍历到哪只才切哪只，
   同一时刻只有一份切片活着，峰值从 O(宇宙) 降到 O(1)。
3. **加载期先把 6000 只 × (lookback+1000) 根全部物化再裁剪**，峰值是稳态的 4 倍以上。
   → `load_universe` 改成按 400 只分批 `load_candles(symbols=...)` + 即时裁剪。
   顺手给 `datasource.tdx.reader._parse_date_int` 加 `lru_cache`：全市场几千万次
   `strptime` 变成几千次，且所有标的**共享同一批 `date` 对象**（object 列只存指针）。
4. **父进程累积上百万 pydantic `Signal`（每条含 metrics dict）。** 实测 OOS-A 的
   136 万条信号 pkl 载入峰值 **2.5GB**（~1.8KB/条）。
   → worker 只回传 `SigLite(strategy, symbol, triggered_at)` NamedTuple
   （`run_verification` / overlay / decay 只用到这三个字段），信号缓存从 267MB 降到
   **31MB**，载入峰值降到百 MB 量级。

### 10.2 工程化：分块落盘 + 断点续跑

`--chunk-days 20 --resume`：每 20 个交易日一块，跑完立刻 `pickle` 到
`data/oos_partial_<窗口>/chunk_NNN_<起>_<止>.pkl`，并**每块重建一次 Pool**
（worker 生命周期短，分配器碎片随进程退出还给系统）。被 kill 也只丢当前块；
`--resume` 会校验块内交易日列表后复用。每块日志打印自身/子进程峰值 RSS +
系统 free/swap，内存趋势可见。

### 10.3 正确性回归（先证明没改结果，再谈省内存）

`scripts/check_slice_regression.py`——三层校验，OOS-A 抽样 8 天（2023 全年均匀取）：

```
2023-01-03 快=2478 慢=2478 快慢一致=True 阶段9=2478 与阶段9一致=True
2023-02-21 快=3330 慢=3330 快慢一致=True 阶段9=3330 与阶段9一致=True
... （8/8 全部一致，共 37,707 条信号）

- 第一层：同一份 candles 上，`DaySliceView`（快）与布尔掩码（慢）的信号集合
  `(strategy, symbol, date)` 逐条相等。
- 第二层：与阶段 9 用慢路径跑出的 `data/oos_signals_oos-a.pkl` 逐条相等
  ——同时证明「分批加载 + date 对象共享」没有改变宇宙。
- 单测：`tests/unit/test_slicing.py`（7 例）——位置切片与布尔掩码 frame 完全相等

## 11. B1 的前置条件（Jeremy 追加需求）

> 复现：
> ```bash
> .venv/bin/python scripts/run_signal_labeling.py --windows IS A B C \
>     --validate-days 3 --out data/signal_labels.json
> ```
> 输出 `data/signal_labels.json`。**事后打标，不重扫**：直接对全市场 K 线重算
> B1 判定式与四类标签，单窗口约 30s（加载 15s + 打标 14s）。

### 11.1 问题

`b1b2b3` 是**裸 B1**：只要 `J<16 或 K≤30` 就报信号，没有任何 MACD 位置 / 量价确认
前置条件，选择性高达 53~63%（等于「半个市场」）。Jeremy 的框架里明确写着
「水下金叉=诱多」「大跌区间里的第一个 B1 不能做」。所以 §2 里 b1b2b3 四段
≈0 超额（-0.5/+0.2/-0.7/+1.0pp）不奇怪——**它把「该做的 B1」和「不该做的 B1」
混在一个桶里平均掉了**。

### 11.2 标签口径（严格按需求定义，没有做任何阈值搜索）

| 标签 | 口径 |
|---|---|
| `macd_side` | 日线 DIF > 0 → 水上；否则水下 |
| `b1_seq` | 同一段水下过程里的第几个 B1；**DIF 上穿零轴作为计数重置点**；水上不编号 |
| `dd120` | 收盘距 HHV(high,120) 回撤 ≤ -20% |
| `ma60_down` | MA60[i] < MA60[i-5]（斜率向下）且 收盘 < MA60 |
| `index_down` | 沪深300（sh000300）20 日涨跌幅 ≤ -5% |
| `vp_confirm` | vr60 ≥ 1.5 且收阳（close>open）→ confirmed；vr60 < 0.8 → unconfirmed；其余 neutral |

口径一致性：20 日收益 = `close[i+20]/close[i]-1`（与 `backtest.forward` 同式）；
基线用 `backtest.baseline.compute_baseline` 的同期个股基线（与 §2 主表同一函数）；
K 线截止窗口结束日，所以窗口最后 20 个交易日的信号没有 20 日收益（与主表同口径）。

**B1 集合是重算的，不是从 pkl 读的**（lite 缓存没有 b1/b2/b3 子类型，而 `b1_seq`
还需要窗口开始之前那段水下的 B1 计数）。重算口径用 `--validate-days` 抽样调用
`b1b2b3` 模块自身的 `scan()` 逐条核对，**9 个抽样日全部一致**（如 2026-03-02
B1 1719 只、2024-07-05 B1 2689 只，逐条相等）。

  但 OOS-A/OOS-B 都反过来。**只有 1.5/4 成立，区分度最差**。
- `index_down`（大盘 20 日 ≤-5%）：四段区间内**全部大幅转正**（+17~+31pp）。
  ⚠️ **这不能解读成「大盘大跌时水下#1 是好信号」**——基线是整段窗口的平均，
  而大盘刚跌 5% 之后的 20 天里几乎所有股票都反弹，这个 +30pp 主要是**区间择时**
  效应，不是选股效应。证据：同一 regime 内部，水下#1 仍然比 seq≥2 差
  （IS +31.3 vs +44.0、OOS-C +19.9 vs +31.8），**相对排序没变**。

**结论**：判定「更差」要用**个股自身的下跌结构**（dd120 优于 ma60_down），
不能用大盘 20 日跌幅——后者混入了市场择时。

### 11.5 硬性过滤规则的代价/收益

保留比例 = 该规则保留的 B1 样本占全部 B1 的比例；后两个数是保留部分的 20 日超额。

| 规则 | IS | OOS-A | OOS-B | OOS-C |
|---|---|---|---|---|
| R0 不过滤（全部 B1） | 100% / -0.0pp / +0.3% | 100% / +1.2 / +0.0 | 100% / -0.0 / +0.0 | 100% / +1.9 / +0.4 |
| R1 只剔「水下#1 无确认」 | 98% / +0.1 / +0.3 | 97% / +1.3 / +0.0 | 98% / +0.2 / +0.1 | 96% / +2.0 / +0.4 |
| R2 只做水下（剔水上） | 84% / +1.5 / +0.7 | 74% / +3.4 / +0.3 | 76% / -0.1 / +0.3 | 65% / +6.3 / +1.2 |
| **R3 水下 且 (seq≥2 或 #1+confirmed)** | **81% / +1.9 / +0.8** | **70% / +3.6 / +0.3** | **72% / +0.2 / +0.4** | **59% / +6.9 / +1.3** |

**诚实的结论**：
1. **R1 方向对但杠杆极小**：因为「水下#1」只占 B1 的 4~5%，只剔它只能把超额胜率
   抬 +0.1~+0.3pp。**它是一条该守的纪律，不是能救 b1b2b3 的药。**
2. **R3 是四段唯一「全部 ≥0」的规则**（+1.9 / +3.6 / +0.2 / +6.9pp），代价是砍掉
   19~41% 的信号。相对不过滤（-0.0 / +1.2 / -0.0 / +1.9），四段各改善
   +1.9 / +2.4 / +0.2 / +5.0pp。
3. **但也别夸大**：R3 之后 OOS-B 仍只有 +0.2pp，而且 R3 的主要贡献来自「剔水上 +
   剔 #1」这两个粗筛，不是精细择时。**加了前置条件的 B1 从「无超额」变成「弱正超额」，
   没有变成一个好策略。** b1b2b3 的根本问题是选择性太差（保留后仍占宇宙 30%+）。
4. 注：以上比例是**对 B1 信号**的，`b1b2b3` 还会发 b2/b3 信号（IS 段 B1 约占其
   总信号的 7 成：28.1 万 / 39.5 万），所以对整个策略的信号削减比例会小于表中数字。

### 11.6 可执行的硬性规则（建议写进 `b1b2b3` 的前置条件）

```
拒绝 B1 买入，当且仅当（四段全负，n>4000/段）：
    DIF < 0                       # 水下
且  该 B1 是本段水下的第 1 个       # DIF 上穿零轴后重新计数
且  NOT (vr60 ≥ 1.5 且 收阳)      # 没有量价确认

推荐（四段全部 ≥0，代价砍掉 19~41% 信号）：
    只做 DIF < 0 且 (b1_seq ≥ 2 或 (b1_seq == 1 且 vr60 ≥ 1.5 且 收阳))
```
