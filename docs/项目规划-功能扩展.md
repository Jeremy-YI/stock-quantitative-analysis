## 数据从「死」到「活」：agent + LLM + MCP（2026-08-31 Jeremy 定方向）

现状盘点（哪些是真数据、哪些是种子数据）：

| 模块 | 数据 | 真/死 |
|---|---|---|
| 板块资金 | 同花顺行业资金流（scripts/fetch_sector_flow.py） | 真（每日快照） |
| ETF 资金流 | 东财 ETF 快照 + 本地通达信日线（scripts/fetch_etf_flow.py） | 真（每日快照） |
| 个股推荐 | 本地 hsjday + 6 策略扫描 + 交易所名称表 | 真（离线计算） |
| 最新消息 | data/news.json | **种子数据** |
| 事件日历 | data/events.json | **种子数据** |
| AI 解读 | DeepSeek + 当日信号 | 真（按需调用） |
| 概览 | 阶段 6 的工程指标（策略胜率/基线/调度） | 与产品四块无关，待重做 |

### 目标架构（三层）

**L1 采集层（把种子数据换成真数据）**
- 消息：财经快讯 cron（金十）落盘 → 结构化；补 web 搜索兜底热点
- 事件：官方日历（FOMC/统计局/交易所财报预约）+ 财报日历接口
- 行情/资金：已有（同花顺 / 东财 / 本地通达信）

**L2 agent 加工层（LLM 干「读 + 判 + 写」）**
- 消息 → 影响评级（改变定价/显著影响/结构性关注）+ 未来导向 + 去重合并（这就是现在种子数据的字段，改由 LLM 生成）
- 事件 → 重要度分级 + 对哪些板块有影响
- 个股 → 信号解读（已有 /ai/interpret）
- 概览 → 一句话盘面结论（regime + 资金 + 信号 + 消息 + 事件 综合）
- 现有资产：services/llm_service.py（httpx 直调 DeepSeek，不引 SDK）

**L3 编排层（MCP + agent loop）**
- MCP server：把「板块资金 / ETF 资金流 / 战法信号 / K线 / 回测 / 事件」暴露成工具，
  让 agent（本地或外部）自己组合调用；参考 Full-stack/5.AI/mcp-typescript-deep-dive（协议现行标准，SDK 版本旧）
- agent loop：定时（收盘后）+ 事件驱动（快讯到达）触发，自己去搜、去算、把结果写回 data/*.json 或 MySQL
- 收编现有 17 个 cron：从「各跑各的脚本」变成「一个 agent 带工具跑清单」

### 落地顺序（建议）
1. 消息真实化（采集 + LLM 加工）——最直接能看到「活」
2. 事件日历真实化（结构化源 + 重要度分级）
3. 概览重做（消费上面两个 + 已有资金/信号，加 AI 一句话）
4. MCP server（Python SDK）暴露只读工具
5. agent loop 收编 cron（先只做「读 + 写快照」，不碰下单）

红线：agent 只做「取数 + 分析 + 写快照」，任何交易动作都不自动化。
